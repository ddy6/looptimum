# Looptimum v1.0.0

v1.0.0 establishes the stable repository-template contract and adds optional
native Ax/BoTorch trial generation around Looptimum's file-backed workflow.
The legacy proxy and direct-BoTorch choices remain available and keep their
defaults. Evaluators continue to run in their own environments.

## Added

- Native Ax 1.3.1 integration in ordinary/full controllers: CPU Sobol
  initialization followed by model-guided generation, flat mixed parameter
  spaces, bound tightening and existing scalar objective policies.
- Immutable optimizer snapshots, journaled allocation-publication repair,
  canonical lifecycle reconciliation and explicit audited optimizer rebuild.
  Worker leases, out-of-order results, budgets and best-observed ranking retain
  their documented meaning.
- A complete pinned CPU dependency profile and portable tooling to build,
  validate and install per-target hashed offline wheelhouses. Install checks
  isolate inherited Python paths and require `pip check` and exact versions.
- Required Linux x86_64/macOS arm64 Python 3.11/3.12 CI lanes, installation
  receipts, real model/restart probes and a mixed external-evaluator example.

## Fixed

Direct-GP fitting can recover from a default-fit line-search failure through
one bounded, explicitly recorded retry. Ordinary GP does not silently switch
to proxy; exhausted fitting preserves the no-allocation boundary. The full
template retains its existing fallback policy.

A fresh comparison completed all 200 campaigns / 2400 evaluations and passed
all seven declared gates. Exactly one case used numerical recovery; all 199
previously successful cases retained the same scores and selected parameters.
This is synthetic-workload evidence for the recorded environment, not a
general performance guarantee. The original failed reference remains available.

## Compatibility and upgrade

- Package `1.0.0` is separate from legacy state `0.3.x`, Ax state `0.4.x`,
  optimizer format `1`, and existing evaluator payload series `0.3.x`.
- Existing legacy campaigns do not need Ax or a forced state rewrite.
  Missing-version/`0.2.x` legacy state retains its warning-and-next-mutation
  upgrade path. Ax conversion requires no outstanding pending work.
- Back up complete state, optimizer files, configuration and environment
  receipts. Exact Ax restoration requires matching semantics and dependencies;
  explicit rebuild creates a new lineage. Released v0.4.0 readers reject Ax
  state. Never edit its version to force a downgrade.
- `failure_reason` remains a deprecated ingest alias throughout v1.x; prefer
  `terminal_reason`. Earliest removal is v2.0.0. The stale v0.4.0 removal
  warning is corrected.
- Service/dashboard/auth/coordination remain preview-only. Service metadata
  becomes `1.0.0-preview`; their registry schema and preview scope do not change.

## Limits

Native Ax does not yet support conditional spaces, heterogeneous categorical
types, forbidden/linear constraints, lexicographic objectives, noise inputs,
measured outcome constraints or true Pareto acquisition. CUDA/MPS generation
and a hosted/distributed control plane are outside this release.
Cross-platform/dependency numerical identity and power-loss durability are
not promised. Local file locking assumes one controller/writer per campaign.

These notes are prepared in source before publication. The published GitHub
tag/release and its exact successful CI run determine release status.
