# Looptimum v1.1.0

v1.1.0 adds opt-in Ax adapter contract 2 and hardens campaign recovery, imports
and website validation. Existing proxy/direct-BoTorch defaults and Ax contract 1
remain available. Evaluators continue to run in their own environments.

## Ax contract 2

Select `optimizer.ax.contract_version: 2` explicitly in ordinary/full controllers.

- Named objective/measurement standard errors, measured outcome constraints and
  evaluator-supplied scalarized score errors. Each modeled metric must have known
  SEMs on every successful observation or unknown SEMs on every successful
  observation; errors are never imputed or discarded. Failed outcomes do not
  establish coverage. Completed-repeat permission retains its existing meaning.
- Exact typed heterogeneous categorical choices, finite conditional trees,
  omitted inactive fields and supported raw linear constraints. Stable internal
  aliases preserve evaluator-facing names and distinguish `1`, `1.0` and `"1"`.
- Eligible forbidden finite choices are pruned from generation only when their
  activation ancestors prove every other forbidden term. Other supported rules
  retain bounded post-filtering. Every candidate passes canonical feasibility;
  failure or exhaustion publishes no partial batch or public evaluation slot.
- Genuine Pareto acquisition with separate measured constraints, explicit
  reference thresholds and direction-correct observed fronts/hypervolume.
- Explicit state `0.5.x` / optimizer format `2`, typed CSV2, complete measurement
  preservation, guarded rebuilds, exact backups and new lineage on upgrade.

See the [contract](../ax-contract2.md) and [supported subset](../ax-support-matrix.md).

## Reliability and integration

- Initialize a fresh imported campaign's seed before fingerprinting it, preserving
  continuation into generation. Validate imported points against campaign bounds,
  linear rules and forbidden combinations before persistence; permissive rejects
  consume no local trial IDs. CSV preserves an objective named `sems` independently
  of its measurement-error columns.
- Harden terminal replay, runtime-limit validation, recovery boundaries and
  campaign-scoped service operations. Canonical reads and terminal/lifecycle
  operations remain available without importing the numerical stack.
- Preserve completed benchmark restore checkpoints when a later command fails.
  Keep failed experiments and their original source/configuration identities.
- Align portable copying, external evaluator tracking, parameter/objective
  guidance, recovery and lean installation instructions.

## Website

- Shared typed case-study records and build-time validation of unique routes,
  copy, metrics, limitations, proof assets, accessible figure context and internal
  CTA destinations. The engineering-mesh and GPT detail pages use shared records.
- Generated HTML is parsed as elements: script/style/template contents cannot
  masquerade as page copy, clickable links, figure context or fragment targets.
  Inline text and escaped content retain their intended meaning.
- Positive/negative site tests and a locked Node.js 24 CI build lane. This release
  also includes the banner, icon and social-preview source updates made after
  v1.0.0. Publication of this software release does not attest to the currently
  deployed site's build identity or complete the outstanding live browser and
  assistive-technology checks.

## Evidence

The separately authorized [repaired-source C5 matrix](../../benchmarks/ax_capabilities/repaired/readout.md)
completed **40/40 campaigns and 960/960 evaluations**, with all runner hard gates
and independent count/metric/canonical/restore audits passed. All 25 Ax restore
checkpoints agree at exact trial IDs/typed choices and absolute float tolerance
`1e-7`. The formerly failing typed-conditional seed 41 completed in 180.34s under
the unchanged 600-second campaign cap, with zero forbidden-branch rejections.

The original 39/40 failed matrix and one-shot continuation remain preserved;
cumulative benchmark use is 1,918 calls. These five-seed synthetic CPU results
do not establish general superiority. Required CI qualifies the exact final
release commit separately from the recorded benchmark source.

## Compatibility and upgrade

- Package `1.1.0` does not renumber legacy state `0.3.x`, Ax contract-1 state
  `0.4.x` / format `1`, or their existing `0.3.x` evaluator payloads. Contract 2
  explicitly selects state `0.5.x` / format `2` and evaluator series `0.4.x`.
- Existing campaigns are not implicitly opted into contract 2. Upgrade requires
  no outstanding work, validated complete measurements, an explicit rebuild,
  backups and a new lineage, or a fresh campaign. Affected pre-pruning development
  campaigns also need an explicit validated rebuild or a new campaign.
- Released v1.0.0 readers reject contract-2 state. Roll back with a complete
  matching pre-upgrade backup; never relabel state or remove optimizer metadata.
- Numerical pins and CPU installation targets remain unchanged. Default package
  installation has no runtime dependencies. The wheel contains the optional
  preview service, not a controller SDK; create portable controllers from the
  repository. Service metadata is `1.1.0-preview`, with preview boundaries retained.

See the [migration guide](../migration-v1.md),
[stability policy](../stability-guarantees.md),
[installation guide](../ax-installation.md) and
[release procedure](../release-guide.md).

## Limits and publication

Ax lexicographic acquisition, multiparent conditional DAGs, unsupported linear
translations, arbitrary forbidden-space compilation and GPU generation remain
outside the supported subset. General rejection can still exhaust its bounded
attempt limit. No cross-platform/dependency proposal identity, general performance
advantage, stable hosted control plane or power-loss durability is promised.

These notes are prepared in source. The new GitHub `v1.1.0` tag/release and its
successful exact-source/tag CI determine publication; the existing v1.0.0 release
is preserved.
